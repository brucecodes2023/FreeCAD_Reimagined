01 · Mandate

Direction before disruption

The first year strengthens the product people already use. Replacement work starts only where measured evidence shows the existing architecture cannot meet the bar.

  • 1

    Upstream-first

    Prefer independently reviewable fixes that can return to FreeCAD. Record every deliberate divergence, its owner, and its exit path.

  • 2

    Two macOS releases

    Support Apple Silicon on the current and previous major macOS versions with reproducible builds, ad-hoc-signed bundles, and launch smoke tests.

  • 3

    Compatible by contract

    Open and migrate editable FCStd documents from FreeCAD 0.21 onward. Preserve common Python API behavior through versioned compatibility shims.

  • 4

    Benchmarks decide

    Measure correctness, latency, memory, and interaction quality before changing internals. A kernel rewrite is an option, never a premise.

First workflow

  1. Sketch
  2. Features

  4. STEP
  5. Drawing
  6. Verify

“Verify” closes the loop: reopen the FCStd file, recompute, compare geometry, and inspect the exported STEP model and production drawing.

02 · Execution

Year-one phases

Four gated phases move from reproducibility to focused improvement. A phase may overlap the next only after its evidence is versioned and repeatable.

  1. Phase 1 · Establish

    Reproducible foundation

    • Build native Apple Silicon applications.
    • Exercise C++, CLI, Pivy, and bundle smoke tests.
    • Pin the current and previous macOS CI lanes.
    • Publish baseline environment metadata.
    Exit: clean checkout to launchable bundle is documented and repeatable.

  2. Phase 2 · Contract

    Migration and baselines

    • Version a representative FCStd 0.21+ corpus.
    • Define common Python API compatibility.
    • Capture workflow correctness and performance.
    • Make failures explicit and reproducible.
    Exit: migration and benchmark scorecards run without manual interpretation.

  3. Phase 3 · Improve

    Upstreamable reliability

    • Prioritize topological naming and recompute faults.
    • Improve feature edits and TechDraw output.
    • Remove migration data-loss paths.
    • Submit bounded changes upstream-first.
    Exit: the workflow meets release gates on both supported macOS versions.

  4. Phase 4 · Prove

    Targeted kernel research

    • Select only unresolved, benchmarked failures.
    • Prototype behind the geometry boundary.
    • Run identical corpus and migration checks.
    • Adopt, defer, or reject with a decision record.
    Exit: evidence supports a bounded adoption decision—not a speculative rewrite.
Expansion gate. Assemblies, direct modeling, and mesh or reverse-engineering workflows enter the roadmap only after the first workflow meets its correctness, migration, and release thresholds.

04 · Compatibility

Migration is a product contract

Files from FreeCAD 0.21 and newer must open as editable documents without silent loss. Migration is forward-only and preserves the original file.

  1. Detect and inventory. Read format and producer metadata, inventory unsupported objects or properties, and choose an explicit versioned migration path.
  2. Restore and migrate in memory. Apply ordered property and object migrations, preserve unknown data when safe, and emit structured diagnostics for every lossy or unsupported case.
  3. Recompute and compare. Recompute without hidden repair, then compare object graph, placement, units, and geometry against corpus expectations.
  4. Save to a copy. Never overwrite the source during migration. Save in the current format to a user-selected copy and retain a migration report.
  5. Reopen and verify. Reopen the copy, recompute again, and run geometry and workflow checks. A warning-free open alone is not success.
Compatibility policy
Input Commitment Save behavior Failure behavior
FCStd 0.21+ Open, migrate, recompute, and remain editable Current format, new copy Stop on unsafe loss; identify affected objects and properties
Older FCStd Best effort outside the year-one guarantee Current format, new copy Explicit unsupported-version diagnostic
Current FCStd Round-trip with no object, property, or geometry loss Normal save Fail the regression gate
New file in old FreeCAD No backward-open guarantee No down-save format Document the boundary; exchange via STEP or supported exports
Common Python API Preserve established scripting paths used by the corpus Not applicable Versioned deprecation and compatibility shim before removal

Non-negotiable failure rule

No silent substitution, dropped property, skipped object, or geometry repair. If safe migration is impossible, leave the source untouched and explain what blocked it.

06 · Adoption control

Kernel adoption gates

OCCT remains the production kernel. A new component advances only when every gate below has written evidence; a whole-kernel rewrite is outside the default plan.

  1. 1

    Measured trigger

    A release-blocking benchmark failure remains after a bounded upstream-first fix has been attempted or ruled out with evidence.

  2. 2

    Isolated boundary

    The prototype sits behind the geometry seam, avoids kernel types in new public APIs, and can be removed without document-format churn.

  3. 3

    Correctness parity

    The same topology, geometry, STEP, drawing, and adversarial corpus passes within documented tolerances.

  4. 4

    Migration safety

    FCStd 0.21+ documents retain editability, stable provenance, and explicit diagnostics across old and new geometry paths.

  5. 5

    Material gain

    The candidate shows a repeatable ≥20% gain on the blocking measure or uniquely resolves a correctness failure that OCCT cannot.

  6. 6

    Stewardship

    License compatibility, third-party provenance, maintenance ownership, security response, and upstream strategy are approved.

Decision outcomes: adopt as a bounded subsystem, continue research with a named evidence gap, or reject and archive the result. “Promising” is not an adoption state.

07 · Controls

Risks and mitigations

The highest risks are uncontrolled divergence and undetected compatibility loss—not a lack of new code.

08 · Record

Foundation decisions

These decisions define year one. Reversals require new evidence, an explicit decision record, and a migration or exit plan.

D-001 · Accepted

Develop upstream-first

Keep work independently reviewable and suitable for FreeCAD whenever practical.

Revisit if a documented product requirement cannot be met upstream without unacceptable harm to the benchmark or compatibility contract.

D-002 · Accepted

Target Apple Silicon first

Support the current and previous major macOS releases as the initial product platform.

Expand after the first workflow and release pipeline meet their gates.

D-003 · Accepted

Guarantee FCStd 0.21+ ingest

Migrate forward to an editable current-format copy; do not promise old FreeCAD can open newly saved files.

Broaden only when corpus evidence supports a larger compatibility window.

D-004 · Accepted

Preserve common Python APIs

Use compatibility shims and versioned migrations for established scripting paths.

Remove an API only after measured usage, deprecation, and a documented replacement.

D-005 · Accepted

Prove one workflow end to end

Optimize sketch → features → edits → STEP → drawing before expanding breadth.

Expand when correctness, migration, performance, and delivery scorecards pass.

D-006 · Accepted

Keep OCCT in production

Treat alternative kernel work as isolated A/B research behind adoption gates.

Adopt only with parity, migration safety, provenance, stewardship, and material measured gain.

Year-one definition of done

A reproducible Apple Silicon bundle passes on both supported macOS releases; every FCStd 0.21+ corpus file migrates without silent loss; the first workflow meets published correctness and regression gates; common Python API fixtures pass; and any kernel decision carries complete benchmark, migration, licensing, and upstream evidence.
